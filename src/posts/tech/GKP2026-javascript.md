# 引入
如果是从一个新手的角度来看，本题的海龟汤笨笨主持人，其实恰好类似于知乎上曾经一个热帖中定义的“真理机”这样东西。感兴趣的可以点击→[如果有一台真理机器只能回答是或不是，能对人类社会作多大贡献？](https://www.zhihu.com/question/324557531/answer/688214123)。从技术上来讲，这其实就是一道布尔盲注的变体。

# 背景

在 Web 应用中，如果服务端直接把用户输入拼接进 SQL 语句，输入就可能不再只是待查询的数据，而是被数据库解释成查询结构的一部分。这正是 SQL 注入的典型成因。
系统命令注入也有类似的问题：外部输入进入命令解释器后，可能改变原本要执行的命令。两者的具体语法和防护方式不同，但都涉及一个危险的边界——本应作为数据处理的内容，参与了代码或指令的解释执行。
这里需要先分清几件事：
- 前端校验可以改善交互，但请求可以绕过前端直接发送，关键防护必须在服务端落实。
- 参数化查询将 SQL 模板与参数值分开处理，是防范 SQL 注入的主要手段。
- 使用 ORM 不代表一定安全；如果仍然拼接原始查询，照样可能引入注入风险。
- 最小权限用于限制数据库账户能够访问或修改的资源，减少漏洞造成的损害，不能代替对注入本身的防护。
下面用 PHP 和 MySQLi 举个例子。以下片段均假设 $mysqli 已经建立了数据库连接。
Yes！PHP 是世界上最好的编程语言！（doge）

风险版（存在注入）
```php
// 直接拼接用户输入，无过滤
$id = $_GET['id']; // 用户输入：1' or 1=1 --
$sql = "SELECT * FROM news WHERE id=$id"; 
$result = mysql_query($sql); // 执行后变成：SELECT * FROM news WHERE id=1' or 1=1 --
//PS: 老师：你确定你们家孩子的姓名是“1' or 1=1”和“admin' OR '1'='1”？家长：是滴是滴（迫真）
```
安全版（参数化查询）
```php
// 使用MySQLi参数化查询，避免注入
$id = $_GET['id'];
$stmt = $mysqli->prepare("SELECT * FROM news WHERE id=?"); 
$stmt->bind_param("i", $id); // 绑定参数（i=整数类型）
$stmt->execute();
```
如上，通过构造特定请求，我们就可以突破后端接口对用户权限的限制，从而达到远程注入效果。
然而，在很多情况下，由于页面逻辑拒绝展示原始数据、数据预处理等设计，我们难以获得回显数据。这种情况下，我们就需要一样武器：盲注。顾名思义，就像是盲人摸象，当无法通过直接获取得到结果时，咱们可以曲线救国：通过数据返回结果在用户端产生的变化，来进行判断。
在盲注手段中，常用的有布尔盲注和时间盲注：顾名思义，布尔盲注就是通过页面结果判断返回结果是否满足某一条件，结合大量分析，达到数据泄露效果；时间盲注就是通过要求服务器在达到某一条件时产生延迟，从而在页面上产生可观测效果，进而分析得出结果。
